# ADR 0009: 確定的な日次制御とファイル・場所の分離

Status: accepted (v0.3.0)

## 判断

公開tool surfaceはV2の4ツールを維持する。日次実行はモデルに手順を選ばせず、CLIが状態とポリシーを判定する。AIエージェントによる手動操作ではレビュー契約を維持する。

## データと操作の契約

- `paths`は場所を表し、移動後も元の行を残す。`files`は観測したファイルのインスタンス、`file_paths`は移動履歴、`path_file_state`は現在の場所との対応を表す。
- サイズと更新日時は鮮度確認に使う。内容ハッシュ、重複の証明、削除の根拠として使わない。
- 移動計画から衝突・更新中・保留対象を除外し、理由を別artifactへ保存する。振り分け先が変わっても保留は解除しない。
- Windows側でapply直前のサイズ/更新日時を確認し、移動先の上書きを禁止する。成功receiptをflushし、DB反映をreceipt単位で冪等にする。
- 中断後は記録済み成功分をDBへ反映する。未記録の操作を同名ファイルから推定しない。記録が不完全なら確認が必要な状態として停止する。
- `run.json`は一時ファイル・fsync・置換で保存する。ステータス表示limitと全runのレビューゲート集計を分離する。
- 作品名をフランチャイズ総称へ短縮しない。辞書・ルールの処理をAIモデルによる抽出と記録しない。
- 過去の参照切れを整理する場合、元レコードの全フィールドを隔離保存し、復元可能性を検証する。推測した場所を挿入しない。

## 日次CLI

`video-pipeline-organize`は既定でDBをコピーし、独立したrunディレクトリへ結果を保存する。`--apply`は、安全な候補に対する実行ポリシーの明示的指定であり、メタデータレビューを承認するものではない。

実行順序はEPG取り込み→棚卸し→抽出/レビュー→計画→ポリシー判定→apply。業務上の失敗は非0終了にする。`--scheduled`は成功時を無言にし、衝突一覧の変更時と失敗時だけ日本語の通知を出す。

## 配布境界

個人の番組辞書、実ドライブ設定、DB、run/artifact、監査履歴は配布しない。公開サンプルを同梱し、ローカル辞書がない場合は空の公開サンプルを使う。配布物は追跡済みソースだけを隔離ステージへ展開してビルドする。

# v0.4.0: 整合性修正と保守CLI

公開V2の4 tool名を維持し、v0.3.0以降の修正をまとめたminor release。
配布先はGitHub Release。npm形式のtarballを添付するが、npm/ClawHub registryへの登録ではない。

## 修正

- metadata反映前のrun/gate/artifact/承認範囲検証、全batchのtransaction、DB内commit receiptによる二重適用防止。
- WAL対応online snapshot、integrity確認、一意backup名、参照中backupの保護。
- workflow writer排他、manifest RMW排他、stale revisionの明示的conflict。
- Gatewayを塞がない公開toolの非同期child実行。deadline/output上限とprocess exit/JSON契約の厳密化。
- metadata commit後のplan失敗を成功扱いせず、再反映も案内しない。
- 長いWindows basenameを拡張子込みで短縮し、native inspection用scriptを配布する。
- Python環境はpluginの外へ置く。reload時に外部interpreterリンクをcompanionとして読み込ませない。
- `pnpm-lock.yaml`をGit管理へ含め、独立checkoutでもfrozen installで同じ依存を再現できるようにする。

## 追加

- `video-pipeline-dedup`: 本放送/再放送を別に保持し、全編の同一性とreviewed coverageを検証した候補だけを復元可能な隔離へ送る。
- `video-pipeline-quarantine-catalog`: 検証済みhandoffから検索可能な一覧を生成する。録画とDBは変更しない。
- `video-pipeline-artifacts`: managed cacheとevidenceを分離し、checksum-bound preview/復元可能なcleanup/legacy archiveを提供する。
- review、routing inventory、native media入力、daily auditとartifact workspaceの回帰を追加。

## 配布と範囲

- packageにはコード、bundled JS、Windows scripts、skills、公開rule/example、Python lockfileだけを含める。
- 個人設定、録画、DB、run/history、作業用artifact、仮想環境、session memoryは含めない。
- package/manifest/Python/npm lockのversionは0.4.0に揃える。
- [ADR-0012](../adr/0012-m0-integrity-boundaries.md)は現行M0の契約。[ADR-0011](../adr/0011-unified-application-kernel-and-recoverable-operations.md)のM1-M5は未実装。
- durable jobs、Windows nativeのlease/journal/reconciler、全host互換、power-loss回復の達成を主張しない。

## リリース検証手順

1. private settings/runtimeを除いたGit indexの内容を独立checkoutへ展開する。
2. `pnpm install --frozen-lockfile`、`pnpm test`、`pnpm run check`を実行する。
3. plugin外の`UV_PROJECT_ENVIRONMENT`で`uv sync --locked`、Python全試験、合成audit probeを実行する。
4. `npm pack`の実tarballをデータとして検査し、version・必要module・allowlist・private data不在を確認する。
5. unpacked packageから空のsynthetic status、invalid resume、CLI helpを検証し、独立OpenClaw stateで登録を確認する。本番DB/録画は使わない。
6. Git commit/tagをatomic pushし、tarballとSHA256SUMSをGitHub Releaseへ添付する。
7. 公開されたtarballを再取得し、SHA256、tag/commit、releaseの公開状態を確認する。

検証結果とdigestはrelease本文とSHA256SUMSに記録する。machine固有のraw receiptは非公開runtime領域へ保存する。

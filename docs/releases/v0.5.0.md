# v0.5.0: 実行の安全性(resume 契約、中断回復、分割 apply)

公開V2の4 tool名は維持する。配布先はGitHub Release(npm形式のtarball)。

## 修正

- #136: `nextActions` / `followUpToolCalls` の params に必ず `resumeAction` を含める。`resumeAction` の省略を暗黙の apply とみなさず、`resume_action_required` と現在有効な `nextActions` を返す。
- #137: 呼び出しの誤り(phase/flow/action 違い、別 run・古い plan、未解決 gate)は run を `blocked` にせず、manifest も変更しない。
- #138: relocate apply を分割実行にし、チャンクごとに DB へ反映する。時間予算を超えると `applying` で一旦返し、`continue_relocate_apply` で続ける。打ち切られた呼び出しは `reconcile_relocate_apply` / `settle_interrupted_move` で回収する。`status` に `applyProgress`。設計は [ADR-0013](../adr/0013-chunked-recoverable-relocate-apply.md)。
- #139: 一部だけ失敗した apply は run を `complete`(outcome `*_apply_partial`)とし、失敗理由の内訳と再プレビューの action を返す。全件失敗のみ `failed`。
- #140: 終端になった run のゲートは閉じる。`cancel_stale_gates` を追加。`status` の `openGates` は active な run のみで、件数は `limit` で打ち切り(`openGatesTotal` に総数、`staleOpenGates` に終端 run の件数)。長期間更新のない active run は `status` の `idleDays` で一覧し、`supersede_idle_runs` でまとめて supersede できる。
- #141: 理由のない禁止(サブエージェント委任、shell での読み取り)をスキル文書から削除し、残す規則に理由を併記。

## 追加

- Windows script `settle_interrupted_move.ps1`(中断した1件の検証つき片付け)。**配備時に `scripts/` へ同期される。**
- 新 phase `applying`、新 resume action `continue_relocate_apply` / `reconcile_relocate_apply` / `settle_interrupted_move` / `cancel_stale_gates` / `supersede_idle_runs`。`status` と `resume` に `idleDays`。

## 範囲と未対応

- 分割実行・回収は relocate のみ。sourceRoot の apply は従来どおり1回の同期呼び出し(#139 の部分失敗の扱いは両方に適用)。
- durable job service、ネイティブ側の排他、一時名コピーは未実装(ADR-0013 の「見送ったもの」)。
- `supersede_idle_runs` は apply が始まった run(`applying`、apply 状態あり、中断した旧 apply のログあり)を対象外にする。先に回収が必要なため。
- `status` は manifest を全件読む。2000 件(各 40KB 前後)で約 0.4 秒だったため、索引化はしていない。
